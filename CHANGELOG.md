# Changelog

Notable changes to the bridge, newest first. Earlier history is in the git log; tracking starts with the first public release.

## [0.6.0] — 2026-09-12

The data-mining release: enumerate the game's files, pull bytes out of them, search localization, and look up any API signature — all from outside the game, most of it with the game closed. Driven by an asset-mining session's field notes, now generalized into [FIELD_NOTES.md](FIELD_NOTES.md).

### Added

- `bg3_vfs_list` — search the game's files by path, packed or loose. The gap it closes was the single biggest friction reported: the in-game API cannot list a directory (Ext.IO exposes only SaveFile/LoadFile/GetPathOverride/AddPathOverride, probed), so every path had to be guessed. Each pak is listed once with divine and cached by name/size/mtime; loose files under `Data/` get their own cached index. The first query pays (~20-40s across a modded install), later ones are sub-second. Covers the three places paks hide — `Data/`, `Data/<subdir>/` (Localization/ carries English.pak, Voice.pak and VoiceMeta.pak, exactly where voice work lives) and the user `Mods/` folder — which is why the base-game `Localization/English/english.loca` (30.8 MB) now resolves where a naive top-level scan finds nothing.
- `bg3_extract_file` / `bg3_read_file` — copy a game file to disk, or read a byte range as text/base64/hex. Loose wins over packed, matching the game's own resolution. This replaces hex-encoding bytes through eval, which doubled payload size against the response ceiling because `Ext.Utils.Base64Encode` does not exist.
- `bg3_loca_search` — reverse lookup over localization: text → handle, or handle → text. `Ext.Loca` only goes handle → text, and its `GetAllTranslatedStringKeys` returns keyed `<guid>_Field` strings rather than the voiced-line handles, which is a misleading name that cost a session real time. The `.loca` is extracted once from `Localization/English.pak` and parsed by the MCP server: 232,878 entries verified, 1.5s first parse, ~40ms afterwards, no context timeout and no payload ceiling.
- `bg3_introspect` — Ext API signatures, enum values and component field lists parsed from the bundled `ReferenceLua/ExtIdeHelpers_v32.lua`: ~400 functions, ~297 enums, ~3,100 classes. `Ext.Audio.PlayExternalSound` comes back as `(uint64, string, string, AudioCodec, number?)` with 4 required arguments and `AudioCodec` lists its labels — the answer to a session that reverse-engineered that call one error message at a time. Complements `bg3_schema`, which reads a LIVE instance and wins when the two disagree.
- `bg3_play_voiceline` — find and audition voice barks, the way to identify a line that carries no localization text at all. `action=find` searches the ~598 VoiceBark resources (by name or path fragment) and reports each one's GUID and its loose `.lsj` definition; `action=play` calls `Osi.StartVoiceBark(bark, character)`. Pairs with `bg3_vfs_list` + `bg3_read_file` to read the handles a bark declares and `bg3_loca_search` to find which have no text.

### Changed

- **Timeouts tell the truth.** "No response" conflated three situations; on the failure path the bridge now checks whether the game process is running and whether the context ever wrote a handshake, and says which of "game not running", "bridge never booted in this context" or "up but did not answer in Nms" actually happened. `bg3_eval` gains `waitMs` so legitimately heavy in-VM work (large file scans, thousands of LoadFile probes) can exceed the default 8s budget deliberately instead of dying at it.
- Docs generalized for publication: the private per-project session notes are distilled into [FIELD_NOTES.md](FIELD_NOTES.md), and the rudimentary `examples/` mods were removed — a showcase mod built entirely through the bridge will replace them.

### Not done, deliberately

- **Response-size pagination.** An asset-mining session hit a ~32 KB ceiling with truncation surfacing as invalid JSON downstream. The bridge's own reader already tolerates torn reads (a parse failure just keeps polling), and the ceiling appears to be the agent harness's tool-result limit rather than the mailbox, so nothing was changed here on speculation. Page large results explicitly — `bg3_read_file` offsets, `limit` parameters, or eval globals that hold state between calls.
- **Playing an arbitrary `.wem`.** `Ext.Audio.PlayExternalSound` needs an event authored for an EXTERNAL source, and the shipped banks expose none (the only Sound resource matching "External" is a cinematic whoosh, probed). No honest wrapper exists until a bank ships such an event.

## [0.5.0] — 2026-08-31

The distribution release: the companion mod ships packed, so other mod developers install it the same way as any mod — no loose folders in their game, no divine on their machine.

### Added

- **The release zip carries a packed `BG3AgentBridge.pak`** next to the exe (plus the mod source under `mod/` for developers and the `ReferenceLua/` signatures). `npm run release` builds the pak with the freshly compiled exe's own `pack` command, so what ships is exactly what a user installs.
- `bg3_flag` — read, set, clear or search Osiris story flags (dialog-granted states such as a deal flag set in conversation). See the 0.4.0 notes below for the probed semantics it encodes.

### Changed

- **`install` is pak-first.** `bg3-bridge install` now copies the prebuilt `BG3AgentBridge.pak` into the game's Mods directory (the same folder mod managers use) — no divine, no mod manager required; modsettings.lsx gets the load-order entry automatically. The two flavors cutover cleanly in both directions: installing one removes the other, because the game serves a pak over loose files and a leftover would silently shadow the hot-reloadable copy. Uninstall removes both flavors plus the load-order entry, and the double-click setup wizard's reinstall/update/uninstall menu works across flavors.
- `install --loose` is the explicit development flavor: loose files into `Data/Mods/` so Lua edits hot-reload with `bg3_reload` — the packed mod's Lua is read once at startup, which is why loose remains the right shape for working on the bridge itself.
- `bg3-bridge pack` builds `BG3AgentBridge.pak` next to the executable (dist/ under Node) instead of installing into the game — pack builds the artifact, install ships it. Still needs LSLib/Divine (`BG3_DIVINE_PATH`); end users never do, because the pak ships prebuilt.

### Fixed

- The install/uninstall state machine now recognises both flavors when detecting an existing install, so "already installed → reinstall/uninstall" no longer misses a pak installed while a loose folder was expected (or vice versa).

## [0.4.0] — 2026-08-30

The field-notes release: every item from a long modding session's improvement list, each fact probed against the live game before it shipped. The generalized findings themselves live in [FIELD_NOTES.md](FIELD_NOTES.md).

### Added

- `bg3_play_effect` / `bg3_stop_effect` — play a visual effect by name or GUID and stop it again. Wraps the silent failure that cost the session real time: `Osi.PlayEffect` takes the Effect resource's GUID and silently no-ops on the name string. The tool resolves the name against the Effect bank first (ambiguous queries are an error listing candidates, unresolved names refuse to fire), reads the resource's `Looping` flag to pick `PlayLoopEffect` vs `PlayEffect` automatically, and tracks every looping handle for stop-by-handle, stop-by-character or clear. Default bind bone `Dummy_Root` (worked for body FX on every race tested). One-shots have no engine handle and burn out after their `Duration`; `StopEffect` does not exist, `StopLoopEffect` does (probed).
- `bg3_effects_near` — lists placed/active effects around a character or position, nearest first, each resolved to effect name + resource GUID + the entity handle it is bound to. Anchored at a character's position resolved server-side. Always runs client-side: placed effect entities are only enumerable from the client VM — the server sees none of them, which is how the session wrongly concluded "no effect here".
- `bg3_teleport` / `bg3_list_levels` — the session's biggest sharp edge, wrapped. `bg3_list_levels` enumerates every playable level name per module from the game's own Editor data (`Data/Editor/Mods/<Module>/Levels/`, loose in the stock install — verified complete at 596 levels across 15 modules; the distribution paks are Larian's proprietary format and deliberately not parsed). `bg3_teleport` validates the target against that list before calling (region/trigger names like `LOW_HouseOfHope2` "succeed" and drop the party into an unloaded blue void), calls the correct 3-argument form, and CONFIRMS arrival by polling `Osi.GetRegion` — `TeleportPartiesToLevelWithMovie` returns immediately while the level streams in over ~15-25 s, so only a polled region change is an honest success. There is no `GetHostLevel`/`GetCurrentLevel` (probed); `Osi.GetRegion` returns exactly the level name this list carries.
- **The `Bridge` table eval chunks get.** Plain globals already persist across eval calls in one VM (chunks share the shared global table — probed; the field notes' "globals reset between calls" was a stale mod install, see below), but the ergonomic surface the notes asked for is now explicit: `Bridge.Scratch` (persistent table, cleared by `bg3_reload` like every global), `Bridge.Osi(name, ...)` returning `{exists, ok, err, result}` — distinguishing missing function, call error and call-returned-nil, which `pcall` collapses into "worked" — `Bridge.Try(fn)`, `Bridge.Fields{...}` (best-effort multi-field returns: one throwing field no longer discards the rest of the cell), `Bridge.Call(op, params)` (dispatch any bridge op directly — deferred ops rejected), `Bridge.EntityFromHandle(s)` and `Bridge.Inspect(v, depth)`.
- **Handle round-trip.** `tostring(entity)` prints `Entity (02000001000034ae)` — the handle form agents end up holding — but `Ext.Entity.Get` rejects that string ("not a valid GUID value"), `HandleToUuid` wants the C++ handle object, and `Ext.Types.Construct` refuses `EntityHandle` ("non-object type"; all probed). `Bridge.EntityFromHandle` and `bg3_entity_inspect` now accept both the full form and the bare 16-hex-digit form, resolving through a `GetAllEntities` scan (159 k entities client-side, one `tostring` each — cheap). A character spawned in the same tick may not be scannable until the next tick.
- `bg3_teleport` / `bg3_list_levels` — the session's biggest sharp edge, wrapped. `bg3_list_levels` enumerates every playable level name per module from the game's own Editor data (`Data/Editor/Mods/<Module>/Levels/`, loose in the stock install — verified complete at 596 levels across 15 modules; the distribution paks are Larian's proprietary format and deliberately not parsed). `bg3_teleport` validates the target against that list before calling (region/trigger names like `LOW_HouseOfHope2` "succeed" and drop the party into an unloaded blue void), calls the correct 3-argument form, and CONFIRMS arrival by polling `Osi.GetRegion` — `TeleportPartiesToLevelWithMovie` returns immediately while the level streams in over ~15-25 s, so only a polled region change is an honest success. There is no `GetHostLevel`/`GetCurrentLevel` (probed); `Osi.GetRegion` returns exactly the level name this list carries. A measurement lesson learned the hard way the same day: the result's `population` count (non-party characters within 40 m of the arrival point) is INFORMATIONAL, not a hollowness verdict — the House of Hope first teleported from an act-1 save rendered as a blue void (modder-reported), but later arrivals into BGO_Main_A scanned as "only 1 named character nearby" while the town streets the modder walked were full of real NPCs; level entry areas are legitimately quiet, so scan outward or walk before calling a world empty. And the arrival point is the level's DEFAULT entry, not a story-safe spawn — the one populated-arrival test dropped the character straight into a chasm; anchor to a known character/position afterwards when a level has scripted entry flow.
- `bg3_flag` — read, set, clear or search Osiris story flags (the dialog-granted states mods key off, e.g. a deal flag granted in a conversation). Found the hard way, with a modder's working console call disproving a wrong conclusion: `SetFlag`/`ClearFlag` need exactly 4 arguments `(flag, objectGuid, dialogInstance, sendFlagSetEventIfChanged)` — the 2-arity overload BINDS and silently no-ops, and the object must be a real character (the zero-GUID object does nothing, even for global-ish flags); runtime flag names are `<Name>_<ResourceUUID>` while the static data only carries the short form, and object-bound flags return NO ROW for a zero-GUID `GetFlag` query. The tool accepts either name form, resolves short → runtime against the ~26k flag declarations (action=find, results carry the current set-state), and set/clear VERIFY by readback, reporting honestly when the silent no-op form is hit. With the recipe, Larian's own debug jump-start chain sets fine: `DBG_Act3_Setup_Good` made the story set `Act3_Visited` itself and spawn setup actors, and after `Debug_Teleport_Act3Start` + `END_General_Debug_GoToAct3` a House-of-Hope teleport landed in a REAL level (the modder confirmed it rendered; the default entry point dropped the character into a chasm, and one mid-load position read made the teleport look like it bounced — it did not).


- **`bg3_osiris_functions` action=signature — the arity-trap killer.** The modder pointed out that the correct parameters for everything were sitting in the Script Extender's generated reference all along, and dropped Osi.lua/Osi.Events.lua/ExtIdeHelpers.lua into the repo's ReferenceLua/ folder. The signature action parses those (983 functions, 320 events, cached) and returns each name's declared parameters with types plus every documented overload arity — `Osi.SetFlag(flag:FLAG, object:GUIDSTRING, dialogInstance:integer, sendFlagSetEventIfChanged:integer)` with 1/2/3-arity overloads, `Osi.CreateAt`'s fixed 7, `Osi.TeleportPartiesToLevelWithMovie(levelName, event, movie)`, the `FlagSet` event's 3 parameters (which is why a 4-arity listener hears nothing). Works with the game closed; degrades with instructions when ReferenceLua/ is missing next to the executable. Declared signatures are the map, not a guarantee — the SE proxy can still reject or no-op an overload form (SetFlag's 2-arity bound and did nothing), so confirm critical calls with action=probe or a real invocation. Redistribution settled cleanly: the three core files come from [LaughingLeader's BG3ModdingTools `generated/` folder](https://github.com/LaughingLeader/BG3ModdingTools/tree/master/generated) (MIT — its license text ships as `ReferenceLua/LICENSE-BG3ModdingTools.txt`, provenance and refresh instructions in `ReferenceLua/README.md`); the SE-generated `ExtIdeHelpers_v32.lua` rides along for `Ext.*` coverage; the unused `CL_LuaLib.lua` and superseded non-v32 helpers were dropped.

- `bg3_resolve_character` fails with structure instead of a bare message: `found:false` plus `diagnostics` — every probe tried and what each returned (the session's literal complaint: "I couldn't tell you *why* it failed, only that it does"). `Ext.Entity.Get` raises on non-GUID-shaped ids rather than returning nil, so every lookup is guarded. `action=host` reports the player-created avatar separately whenever control and avatar differ (`GetHostCharacter` follows control and does not revert on resurrect); `action=resolve` includes the avatar when the resolved character is not it. Characters now carry world `position` (for `bg3_effects_near` anchoring and teleport distance checks without a second call).
- `bg3_spawn_character` validates the template is a ROOT template up front — story character-INSTANCE uuids (from `DB_Players`/Osiris events) and non-root templates both make `Osi.CreateAt` "succeed" while spawning nothing; both `GetRootTemplate` and `GetTemplate` return nil for instance uuids (probed), and each failure names its case and the fix. The response reports `confirmed` — whether a live entity actually exists at the returned id. Spawns are spaced ~300 ms apart at the tool layer: a 21-spawn burst plus a full animations-table scan left the server context unresponsive for a while in the session. The template-means-spawn default moved into the Lua op so direct dispatch (`Bridge.Call`) behaves like the tool.
- `bg3_eval` degrades gracefully on deep results: a live component dumped whole used to fail the entire cell at Ext.Json's depth limit; results that cannot encode (probed with headroom for the response envelope — the mailbox walks `result.values[i]` several levels deeper than a bare encode, so a bare-depth probe can pass while the real reply dies) are re-encoded as `Bridge.Inspect` snapshots, scalars first, depth 3, `degraded` flagging it. `bg3_entity_inspect` accepts handle strings; `bg3_reload` documents that a reset does not re-fire the game's session-loaded events; `bg3_eval`'s description documents the persistence and helper surface. Tool count 21 → 26; README gains a "which tool for which layer" paragraph (resources → templates → stats/static data → runtime state).

### Fixed

- The Osi proxy returns a placeholder for missing names whose comparison to nil itself RAISES (probed live) — `Bridge.Osi` therefore classifies existence from the call's error text ("attempt to call a nil value" = missing, any other error = exists but failed), the same way `bg3_osiris_functions` probe does.


## [0.3.0] — 2026-08-24

First public release. Versions below the entries are commit dates, not separate releases.

### Added — 2026-08-24

- `bg3_resolve_character` — resolves any character reference (bare UUID, prefixed template-name form, or display name) to a stable identity: bare uuid, prefixed form, display name, whether it is the player-created Tav (`AvatarComponent`, stable across control hand-offs and death), whether it is host-controlled now, HP, and dead/downed state. `action=party` lists the party the same way; `action=host` resolves the control-holder. Addresses the identity minefield where `GetHostCharacter()` returns a bare UUID and follows control while Osiris events deliver prefixed forms that fail bare-string equality.
- `bg3_life` — damage/heal/setHp/fullHeal/kill/down/resurrect for a character, reporting before/after HP and dead/downed state after a settle window, plus the `method` used and a faithfulness `caveat`. HP is set via `Osi.SetHitpoints` (verified present against the live game), falling back to a `HealthComponent.Hp` write + replicate when unavailable; the settle read surfaces an ineffective queued call as `after != target` rather than a false success. Setting HP is still not a damage/attack event, so combat and death triggers can differ from a real hit (a raw write to 0 can leave a "limbo death" inside a scene that a cutscene/scene-manager mod has suppressed); `down` applies DOWNED, `resurrect` uses `Osi.Resurrect` when present. Backs the death/downing testing the field notes call out.
- `bg3_osiris_functions` — `action=list` enumerates the live `Osi` table (`pairs(Osi)`, ~1303 names on SE v32) filtered by substring; `action=probe` calls specific names with zero arguments inside pcall and classifies SE's error text to report existence without triggering mutating calls. Confirms existence, not arity.
- `bg3_vfs_probe` — reads a path through the game VFS (`Ext.IO.LoadFile`) and reports the byte length served, the decisive test for whether the live copy is the pak or a loose file when both exist.
- **Double-click setup (and uninstall).** Double-clicking `bg3-bridge.exe` (or running it with no arguments in an interactive console) installs the companion mod and prints the MCP config block to paste into your agent, then holds the window open — deliberately minimal, since the agent handles connecting and testing once the config is in. If the mod is already installed it instead offers reinstall/update or **uninstall**, so removing it is as easy as installing. Also available as `bg3-bridge setup`; `bg3-bridge uninstall` is a CLI alias for `install --uninstall`. When an MCP client launches the exe with no arguments over a pipe it still starts the server exactly as before (dispatch branches on `stdin.isTTY`); `bg3-bridge serve` forces server mode. `install` gained a `performInstall` core that throws rather than exits, so setup can report a failure (e.g. the game still open) and pause instead of the window vanishing.

### Changed — 2026-08-24

- `bg3_reload` now waits for the reload to complete by default and confirms it without depending on Script Extender logging: it records the handshake file's timestamp, triggers the reset, waits for `Bridge.Start` to rewrite that handshake (the definitive "VM rebooted" signal), then pings the fresh VM and returns `{reloaded, rebooted, responsive, durationMs, capabilities}`. A Lua syntax error in a reloaded script stops `Bridge.Start`, so the handshake never advances and it correctly reports `reloaded:false`. `wait=false` restores fire-and-forget. (Replaces the initial log-marker approach, which reported false negatives when runtime file-logging was disabled.)

### Added — 2026-08-12

- `bg3_trace_events` — captures the ordered Osiris story-event stream (`>>> event Name(args)` lines) from the Osiris Runtime log: `start` marks a position, `read` returns events since, filtered by an event-name regex and/or an entity substring (a bare UUID matches its prefixed template-name form in event arguments). Log lines carry no timestamps, so the stream is ordered but not timed.
- `bg3_schema` — component/resource field introspection read from live instances: `action=components` lists an entity's components as the union of `GetAllComponents()` and `GetAllComponentNames()` with an `accessible` flag per row (the two listings disagree, and a listed name is no guarantee property access works — `e.StatusManager` raises where `e.StatusContainer` succeeds); `action=fields` dumps a component's field names, value types and scalar previews; `action=resource` samples a resource bank the same way (loaded entries only).
- `bg3_eval` — captures `print`/`Ext.Utils.Print` output emitted during the call (and during timers it scheduled, up to a `captureMs` window) and returns it as `prints`; `modContext` runs the chunk with another mod's `PersistentVars`/`ModuleUUID` swapped in; `pollUntil` re-evaluates a Lua predicate until truthy or `timeoutMs` and reports the outcome as `polled`. Deferred replies ride a new asynchronous path in the mailbox protocol (`Bridge.DEFERRED`/`Bridge.Respond`), backward-compatible with synchronous handlers.
- `bg3_read_log` — `logType` (`extender`/`osiris`) picks the channel by filename prefix instead of substring guesswork, `head` reads from the top, and `cursor` follow mode returns only lines appended since the previous call, flagging log rotation instead of silently resuming.
- `bg3_list_logs` — groups files into game sessions (each launch writes an Extender and an Osiris log seconds apart) and defaults to the newest 10.

### Fixed — 2026-08-12

- `bg3_spawn_character` with a template but no explicit `action` no longer lists instead of spawning: `action` now defaults to `spawn` when `template` is given, `list` otherwise. Previously a template-only call returned `{count: 0, spawned: []}` with nothing spawned and no error.

### Added — 2026-08-08

- `bg3_animation` — auditions animations on a character (`find`/`play`/`loop`), swaps the whole locomotion set (`animset`), and overrides the idle via a live-edited `StillAnimationType` on a clean carrier status, all restored by `clear`. `animset` writes a status `DynamicAnimationTag` pointing at an `AnimationSetPriority` entry (reusing a clean existing carrier when one carries the tag), replacing idle, walk and run with free movement — the mechanism animation-replacement mods use, mapped from the On All Fours Toggle mod (toggleable passive → hidden status → animation-set tag). Other probed facts: `PlayAnimation` wants the bare AnimationShortName GUID (the `GUID(name)` display form is a silent no-op); `PlayLoopingAnimation`'s true signature is 8 arguments with the animation in position 3 (arities 2-6 all fail), looping animations continuously and holding statue poses, ended by `Osi.StopAnimation(character, 1)` — the channel number, not a name (the bogus-name cancel in the Emotes mod is only a pose interrupt); looping signature credit: Emotes mod (claravel). The status `AnimationLoop` field is ignored on BOOST statuses, and pak path-shadowing a base idle GR2 does not override it (tested), so single-animation idle replacement is limited to the still-animation enum. Resolves each animation's natural length from the Animation bank where the GR2 path carries the short name.
- `bg3_spawn_character` — spawns an NPC from a character template UUID beside the host character (or a `near` anchor, or exact `x`/`y`/`z`), tracks what it spawned, and removes them with `despawn`/`clear`. Wraps the `Osi.CreateAt` arity trap (exactly 7 arguments, fifth is `temporary`, and overload errors never say so).
- **Single-file exe distribution.** `bg3-bridge.exe` is the MCP server and every maintenance command (`install`, `configure`, `check`, `pack`); modders no longer install Node.js. MCP config shrinks to a single `command` with no args.
- `npm run build:exe` — Bun-compiled binary with the package version baked in via `--define`. Bun is build-time-only (`tools/bun.exe`, gitignored).
- `npm run release` — builds the exe and assembles `dist/bg3-agent-bridge-vX.Y.Z.zip` (exe + `mod/` + README + LICENSE) using the `tar.exe` that ships with Windows 10+.

### Changed — 2026-08-08

- CLI logic moved to `src/cli/`, shared by the exe dispatcher and the Node wrappers in `scripts/` — one implementation, both entry points. The Node flow (`node scripts/*.mjs`, `node dist/index.js`) still works unchanged for source users.
- README setup flow rewritten for the exe and condensed overall (~27% less prose): deduplicated the install/connect steps, fixed the release zip name (v0.1.0 → v0.2.0) and the tool count (14 → 18).

### Fixed — 2026-08-08

- Exe detection: Bun URL-encodes `~BUN` as `%7EBUN` in `import.meta.url`, so the first check never matched.
- Direct-run guards: inside a Bun-compiled exe every module's `import.meta.url` is the exe's own URL, which made each CLI module auto-run on import. Guards now return false in exe mode; the dispatcher is the only entry.
- Bridge error classes carry explicit `name`s; minification had mangled `constructor.name` into noise in diagnostics.

### Added — earliest work

- `bg3_find_stat` with display-name search by default, static data search, effect reverse lookup, status and item previews, fuzzy template search, sound capture and auditioning.
- Dev installer that works without a dev toolchain; generated MCP config block instead of hand-typed paths; client config writer with `--write`/`--path`.
- Prominent security note: the bridge executes arbitrary Lua in the live game; uninstall when done.
- `RequiredVersion` set to the version actually developed against (SE applies old-version compatibility semantics to lower numbers).
